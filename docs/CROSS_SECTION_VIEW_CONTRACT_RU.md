# GeoKZ — UI/view-model корреляционного разреза (RU)

## Назначение

Endpoint визуального разреза предназначен для будущего PySide6/web клиента. Backend не рисует графику, но возвращает полностью подготовленную структуру: порядок колонок скважин, единую вертикальную шкалу, реперы, интервальные полосы, корреляционные линии и предупреждения о несовместимых данных.

```text
POST /api/v1/correlation/wells/view
```

Запрос использует тот же `WellCorrelationRequest`, что и базовая корреляция:

```json
{
  "reference_well_id": "UUID",
  "well_ids": ["UUID"],
  "language": "ru"
}
```

Существующий `POST /api/v1/correlation/wells` не изменён и остаётся источником аналитических differences. View endpoint сначала вызывает тот же `WellCorrelationService`, а затем только преобразует результат в UI-ready contract. Поэтому визуальный слой не вводит новую геологическую интерпретацию.

## Шкала глубин

`depth_axis` содержит:

- `depth_reference` — одна явная система глубин для всего разреза;
- `unit=m`;
- `direction=DOWN`;
- `min_depth_m`, `max_depth_m`;
- `padding_m` для визуального поля сверху и снизу.

Выбор системы выполняется детерминированно:

1. TVDSS;
2. TVD;
3. MD.

Приоритет применяется к уже сопоставимым marker/reservoir differences. Если сопоставимых пар нет, GeoKZ выбирает первую доступную систему в том же порядке. Если безопасно отображаемых данных нет вообще, используется техническая TVDSS-шкала `0..1`, `has_renderable_data=false` и обязательное предупреждение `NO_RENDERABLE_DATA`.

GeoKZ не пересчитывает интервалы из MD в TVD/TVDSS без подтверждённой траектории. Интервал выводится на шкалу только если его `depth_reference` совпадает с `depth_axis.depth_reference`.

Для репера могут использоваться явные `tvdss_m`, `true_vertical_depth_m` или `measured_depth_m`; если нужное альтернативное значение отсутствует, допускается `depth_m` только при совпадении `marker.depth_reference`.

## Колонки скважин

`columns[]` сохраняет порядок запроса: сначала опорная скважина, затем выбранные соседние скважины без дублей.

Каждая колонка содержит:

- `column_index` — стабильный индекс для layout;
- `well` — существующая `WellCard`;
- `is_reference`;
- `distance_from_reference_m`;
- `markers[]`;
- `intervals[]`.

`marker` и `interval` имеют `renderable`. Если значение нельзя безопасно перенести на общую шкалу, `renderable=false`, координата на шкале возвращается как `null`, а исходная система глубин сохраняется. Клиент не должен самостоятельно конвертировать такие элементы.

## Корреляционные линии

`correlation_lines[]` уже содержит координаты концов относительно колонок и глубинной шкалы.

Стабильные `kind`:

```text
MARKER
HORIZON
```

`MARKER` создаётся только из `MarkerDifference(comparable=true)` в выбранной системе глубин.

`HORIZON` создаётся только из `ReservoirDifference(comparable_thickness=true)` и связывает середины подтверждённо сопоставленных интервальных полос. Это визуальная связь уже найденной пары интервалов, а не новое автоматическое стратиграфическое решение.

Каждая линия содержит:

- `key` — `marker_code` или имя горизонта;
- `depth_reference`;
- `from_column_index`, `to_column_index`;
- `from_well_id`, `to_well_id`;
- `from_depth_m`, `to_depth_m`.

Линии строятся относительно выбранной опорной скважины, потому что текущая аналитическая корреляция также reference-based. Клиент не должен сам перестраивать связи «сосед-сосед».

## Предупреждения

Стабильные коды:

```text
DEPTH_REFERENCE_MISMATCH
NON_COMPARABLE_MARKERS
NON_COMPARABLE_INTERVALS
NO_RENDERABLE_DATA
NO_CORRELATION_LINES
```

`DEPTH_REFERENCE_MISMATCH` означает, что часть данных конкретной скважины присутствует в ответе, но не отображается на общей шкале.

`NON_COMPARABLE_MARKERS` и `NON_COMPARABLE_INTERVALS` не являются ошибкой HTTP: GeoKZ сохраняет несопоставимость как часть научного результата и не рисует ложную линию.

`NO_CORRELATION_LINES` означает, что колонки/данные могут отображаться, но подтверждённых пар для соединения нет.

Текст warnings локализуется по `language=ru|kk|en`; коды остаются неизменными и должны использоваться клиентом для логики UI.

## Безопасность интерпретации

View-model не меняет verification status, не создаёт новые markers/intervals и не публикует факты. Он только визуализирует результат существующей корреляции.

Правила:

- TVDSS/TVD/MD не смешиваются молча;
- UNKNOWN depth reference не считается совместимой системой;
- отсутствие данных показывается явно;
- correlation line существует только для уже сопоставимой пары;
- `VerificationStatus` каждого marker/interval сохраняется в contract;
- visual section не заменяет экспертную геологическую интерпретацию.

## PySide6

Будущий экран должен использовать backend contract напрямую:

1. отправить выбранные well IDs и reference well;
2. построить вертикальную шкалу из `depth_axis`;
3. расположить well columns по `column_index`;
4. рисовать только элементы `renderable=true`;
5. построить линии из `correlation_lines`;
6. показать `warnings` и `policy_note` пользователю.

PySide6 не должен повторять алгоритм выбора глубинной системы или вычислять пары корреляции самостоятельно.
