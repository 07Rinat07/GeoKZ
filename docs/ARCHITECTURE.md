# Архитектура GeoKZ v0.1

## Слои

1. **Хранилище** — PostgreSQL/PostGIS.
2. **Предметная модель** — SQLAlchemy.
3. **HTTP-контракт** — FastAPI/OpenAPI.
4. **Клиенты** — будущий PySide6, web-интерфейс, импортёры и QGIS-интеграция.
5. **Внешний ИИ-агент** — только подготовка черновиков и очереди проверки.

## Почему API отделён от интерфейса

Одинаковая предметная логика будет использоваться:

- Windows-приложением одного геолога;
- браузерной редакторской панелью;
- локальной сетью организации;
- пакетными импортёрами PDF/CSV/JSONL;
- интеграциями с GIS.

## Доказательная модель

Факт хранится отдельно от его подтверждений. Несколько источников могут:

- подтверждать факт;
- противоречить ему;
- лишь упоминать его;
- давать контекст.

Противоречие не удаляет один из вариантов. Оно оформляется отдельной записью
`conflict_record` и направляется эксперту.

## Геометрия

Все рабочие геометрии хранятся в EPSG:4326. Исходная система координат,
точность и способ получения должны сохраняться отдельно.

Старая карта не становится точной цифровой геометрией только после сканирования.
Статус `DIGITIZED` или `APPROXIMATE` обязателен.
