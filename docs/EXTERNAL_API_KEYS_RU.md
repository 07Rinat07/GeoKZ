# GeoKZ — получение и настройка API-ключей внешних источников (RU)

Актуальность: 2026-09-04.

## 1. Зачем GeoKZ нужен API-ключ

GeoKZ может работать полностью с локальной базой без внешнего API. API-ключ требуется только для тех внешних источников, которые сами требуют авторизованный программный доступ.

Для официального портала открытых данных Республики Казахстан `data.egov.kz` ключ используется для REST API v4 и синхронизации открытых наборов данных, подключённых к GeoKZ.

GeoKZ никогда не должен хранить реальный API-ключ в Git, README, исходном коде, issue, pull request, скриншоте или пользовательской документации.

## 2. Где получить ключ data.egov.kz

1. Откройте официальный портал открытых данных Республики Казахстан: `https://data.egov.kz/`.
2. Авторизуйтесь на портале через доступный способ входа eGov.
3. Откройте раздел **«Разработчикам»**.
4. Перейдите в **«Кабинет разработчика»**.
5. Найдите раздел API-доступа / API key и создайте либо скопируйте персональный ключ разработчика.
6. Сохраните ключ в менеджере секретов или локально в `.env` GeoKZ.

Интерфейс государственного портала может меняться. Если пункт выдачи ключа перемещён, используйте разделы «Разработчикам», справку портала или официальную поддержку eGov/Open Data.

## 3. Куда вставить ключ в GeoKZ

В корне проекта создайте локальный `.env` из шаблона:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и заполните только локальное значение:

```env
GEOKZ_EGOV_API_KEY=ВАШ_РЕАЛЬНЫЙ_КЛЮЧ
```

Не добавляйте кавычки, если сам ключ их не содержит.

После изменения `.env` перезапустите GeoKZ API / Docker Compose, чтобы настройки были перечитаны.

## 4. Что нельзя делать с ключом

- не коммитить `.env` в Git;
- не вставлять ключ в `README.md`;
- не помещать ключ непосредственно в Python-код;
- не публиковать ключ в issue/PR;
- не отправлять ключ в чат или почту без необходимости;
- не показывать его на скриншотах;
- при подозрении на утечку — отозвать/заменить ключ в кабинете разработчика.

В репозитории должен оставаться только безопасный шаблон:

```env
GEOKZ_EGOV_API_KEY=
```

## 5. Проверка настройки в GeoKZ

После запуска API откройте Swagger:

`http://localhost:8000/docs`

Проверьте каталог официальных наборов:

```text
GET /api/v1/integrations/kazakhstan/catalog
```

Поле `api_key_configured=true` означает, что GeoKZ видит непустой ключ в конфигурации. Это ещё не подтверждает, что портал принял ключ.

## 6. Регистрация официальных казахстанских наборов

В Swagger выполните:

```text
POST /api/v1/integrations/kazakhstan/register
```

GeoKZ зарегистрирует известные официальные источники в таблице внешних источников. Регистрация не перезаписывает проверенную геологическую базу.

## 7. Первый безопасный тест синхронизации

Для списка нефтегазовых месторождений:

```text
POST /api/v1/integrations/kazakhstan/kz-egov-oil-gas-fields/sync
```

Для лицензий на геологическое изучение недр:

```text
POST /api/v1/integrations/kazakhstan/kz-egov-geological-study-licenses/sync
```

Полученные записи сначала сохраняются в RAW/staging слое:

```text
data.egov.kz
  → RAW
  → checksum/diff
  → normalization
  → matching
  → review
  → verified GeoKZ master data
```

Внешний API не имеет права автоматически перезаписывать подтверждённые данные GeoKZ.

## 8. Если синхронизация не работает

Проверьте последовательно:

1. существует ли `.env`;
2. задан ли `GEOKZ_EGOV_API_KEY`;
3. перезапущено ли приложение после изменения `.env`;
4. показывает ли `/api/v1/integrations/kazakhstan/catalog` значение `api_key_configured=true`;
5. доступен ли `https://data.egov.kz/` из вашей сети;
6. действителен ли ключ в кабинете разработчика;
7. не изменил ли портал версию/схему конкретного набора.

Типичные ответы GeoKZ:

- HTTP `503` — отсутствует или некорректно настроен локальный API-ключ/connector;
- HTTP `502` — внешний портал ответил ошибкой либо вернул неожиданный протокол;
- HTTP `404` — неизвестный код набора GeoKZ.

## 9. Текущие официальные наборы GeoKZ

На этапе `v0.2-dev` зарегистрированы:

- `kz-egov-oil-gas-fields` — нефтегазовые месторождения Республики Казахстан;
- `kz-egov-geological-study-licenses` — лицензии на геологическое изучение недр.

Список будет расширяться по мере проверки новых официальных открытых источников.

## 10. Другие API-ключи

Для будущих интеграций применяется то же правило:

```text
секрет пользователя/организации
  → environment/.env или системное хранилище секретов
  → Settings
  → Connector
```

Ключи никогда не должны становиться частью доменной модели геологических данных.
